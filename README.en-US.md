# DOCX Template Translator Skill

This is a Codex skill designed to convert **LaTeX, PDF, Markdown, or crude DOCX files** into a specified Word template format.

It is tailored for use cases such as graduation theses, degree dissertations, unit reports, and standard documents, particularly where **pandoc’s default DOCX output falls short** and strict adherence to school or institutional Word templates is required.

## Quick demonstration

The repository includes a minimal, runnable example located at [`examples/minimal_markdown/`](examples/minimal_markdown/). To run it, execute the following in the repository’s root directory:

```bash
python examples/minimal_markdown/run_example.py
```

This script generates a sample template on the spot, runs the inspect, adaptive, and finalize steps, and outputs a PDF preview in a Windows + Word environment. The two images below were created using the same `sample.md` and the same Zhengzhou University degree thesis template, with the first image processed through this project’s adaptive pipeline and the second image generated using only `pandoc --reference-doc`:

**This project’s output: pandoc → adaptive pipeline → Word finalize**

![Preview of the main body produced by this project](examples/minimal_markdown/expected/preview.png)

**Direct pandoc baseline: only using `pandoc --reference-doc`**

![Direct pandoc baseline](examples/minimal_markdown/expected/pandoc_baseline.png)

> Both images use the same input and template, but **the numbering context differs**: This project’s output preserves the pre-existing content and chapter numbering in the real template, so the example section is appended after the original chapters in the template (e.g., showing numbers like `4.7` / `8.7`, depending on the template’s current content). In contrast, the direct pandoc baseline creates a new document from `sample.md`, reusing only the styles defined by `--reference-doc`, and thus starts numbering from Chapter 1 (e.g., `1.5`).
>
> The comparison shows that `pandoc --reference-doc` can reuse some styles, but it only knows about style definitions and does not understand the semantics and layout constraints of the school template for body text, tables, figures, and formulas. Charts, equations, and tables are more likely to cross pages, spacing is loose, and tables are not in the three-line table format required by the target template. This project first inspects the template, then uses the adaptive pipeline to map the body, figure captions, equations, and tables, and finally uses Word finalize to export, making it more suitable for strict school/institution templates.
>
> The image of this project’s output was generated using the following command, then cropping the main body area from page 20:
>
> ```bash
> python examples/minimal_markdown/run_example.py \
>     --template <your local template.docx> \
>     --preview-pages "20"
> ```
>
> If you don’t provide `--template`, `run_example.py` will use the lightweight sample template generated by `build_template.py`, and the output will be more simplified but fully reproducible. `--preview-pages` defaults to `"1-4"`, which is sufficient for the demo template. See [`examples/minimal_markdown/expected/README.md`](examples/minimal_markdown/expected/README.md) for details.

The inspect, adaptive, and preview steps can run on macOS, Linux, or Windows. The finalize step, which uses Word COM to update fields and export PDF, is only available on Windows with Microsoft Word installed.

## Why not use pandoc directly?

Pandoc is excellent for initial conversion, especially for Markdown and LaTeX source files. The `--reference-doc` option can reuse Word styles, but it only knows about "style definitions" and does not understand the semantics of pages and paragraphs in the template.

Strict templates often encounter these issues:

- Cover, English cover, and declaration page are not filled out correctly.
- Signature page, authorization page, header/footer do not conform to the template.
- Template style names are misleading, e.g., `Body Text` is actually used for the English cover.
- Body paragraphs are mistakenly set to cover style.
- Figure captions are missing numbers.
- Tables are not converted to three-line tables.
- Bibliography citations are not superscript, cannot be linked.
- Hyperlinks are displayed in blue with underlines, which is not suitable for printed theses.
- Table of contents, page numbers, and cross-references are not updated.
- No automatic PDF export for visual inspection.

This skill is not intended to replace pandoc, but to combine pandoc, Word, and Python, allowing AI to automatically write a specialized post-processing script based on the user’s uploaded Word template and source files.

## Existing project research

- [pandoc](https://pandoc.org/MANUAL.html) supports `--reference-doc`, which can reuse DOCX styles. According to its official documentation, the body content of the reference DOCX is ignored, and it mainly uses the styles and document properties within it.
- [Quarto DOCX](https://quarto.org/docs/reference/formats/docx.html) also supports `reference-doc`, table of contents, chapter numbering, and citations and bibliography links.
- [pdf2docx](https://github.com/ArtifexSoftware/pdf2docx) can convert native PDF to DOCX. Its documentation states that it uses PyMuPDF to parse PDF, regularizes the layout, and generates Word using `python-docx`.
- [python-docx-template](https://docxtpl.readthedocs.io/) is suitable for variable replacement in pre-made Word templates using Jinja-style templates.
- [MDDoc](https://www.mddoc.app/) is a commercial Markdown to Word conversion tool that can map Markdown elements to uploaded Word templates.
- [wmvanvliet/pandoc-tutorial](https://github.com/wmvanvliet/pandoc-tutorial) demonstrates the reality of complex LaTeX to DOCX conversion: pandoc can complete most of the conversion, but final template adaptation often requires custom processing.
- [openclaw/pdf-to-docx skill](https://playbooks.com/skills/openclaw/skills/pdf-to-docx) is a PDF to DOCX skill based on pdf2docx.

This project differs in that it is not a fixed converter, but an **open AI template reconstruction workflow**. It allows AI to first inspect the user’s uploaded Word template, then generate a specialized Python post-processing script for that template, making it suitable for strict templates from schools, institutions, and journals.

## Core concepts

1. Treat LaTeX/PDF/Markdown as **content sources**.
2. Treat `.docx` templates as **layout sources**.
3. First use pandoc, Word import, or other tools to generate a rough body DOCX.
4. Inspect template styles, paragraphs, numbering, tables, hyperlinks, and OOXML.
5. Let AI write or modify a Python reconstruction script based on template inspection results.
6. Use `python-docx` and underlying OOXML operations to generate the final DOCX.
7. Use Word COM to update table of contents, page numbers, and other fields, and export PDF.
8. Render the PDF into a preview puzzle for quick inspection of cover, table of contents, charts, formulas, and references.

## Supported inputs

- LaTeX projects: `main.tex`, chapters, images, BibTeX.
- Markdown files.
- Native digital PDFs.
- Already roughly converted Word files.

If LaTeX or Markdown source files are available, prioritize using them. PDFs have weaker semantic information and are not suitable as primary input.

## Skill content

The skill is located at:

```text
skills/docx-template-translator/
```

It includes:

- `SKILL.md`: AI workflow.
- `scripts/inspect_docx_template.py`: Inspect Word template structure.
- `scripts/adaptive_docx_pipeline.py`: A modifiable DOCX reconstruction script starter.
- `scripts/finalize_word_docx.py`: Update table of contents/paragraphs through Word and export PDF.
- `scripts/validate_docx_conversion.py`: Structural layer QA (placeholder / order / title styles / chapter headers / protected front page format drift).
- `scripts/validate_docx_render.py`: Rendering layer QA (TOC field existence / numId↔abstractNum consistency / multi-level title format string / bibliography counter independence / main body header static text residual / PDF field error string).
- `scripts/inject_toc_field.py`: Injected `{ TOC \o "1-3" \h \z \u }` field after "Table of Contents / Contents" title in an idempotent manner, fixing the common bug where the table of contents page only has a title and the TOC field is missing.
- `scripts/set_styleref_header.py`: Change the static text (e.g., `Acknowledgements`) in a specified `headerN.xml` to a `STYLEREF <styleId>` field, so that the main body header updates dynamically with the chapter.
- `scripts/render_pdf_preview.py`: Render PDF into a preview puzzle.
- `references/pandoc-limitations.md`: Explanation of differences with pandoc’s default functionality.
- `references/zhengzhou-case-study.md`: Case study of Zhengzhou University graduation thesis template conversion.

## Installation

Copy the skill to the Codex skills directory.

macOS / Linux:

```bash
mkdir -p ~/.codex/skills
cp -r skills/docx-template-translator ~/.codex/skills/
```

Windows (PowerShell):

```powershell
New-Item -ItemType Directory -Force -Path "$HOME\.codex\skills" | Out-Null
Copy-Item -Recurse -Force skills\docx-template-translator "$HOME\.codex\skills\"
```

You can then call it like this:

```text
Use $docx-template-translator to convert my LaTeX thesis into Word using this .docx template.
```

If you need to use the same skill folder in Claude Code, Cursor, or other AI agents, refer to the [Compatibility](#compatibility) section below.

## Python dependencies

Recommended installation:

```bash
pip install python-docx pywin32 pymupdf pillow
```

Optional:

```bash
pip install pdf2docx
```

When converting LaTeX or Markdown to DOCX, it is recommended to install pandoc separately.

For the final step of updating the table of contents and exporting PDF, it is recommended to use the native Microsoft Word on Windows, as the script uses Word COM to update fields and export PDF.

## Typical workflow

1. The user provides source files and a Word template.
2. Codex inspects the template:

```bash
python scripts/inspect_docx_template.py template.docx --out template_report.json
```

3. Codex generates a rough body DOCX:

```bash
pandoc main.tex --citeproc --reference-doc template.docx -o body.docx
```

4. Codex modifies `scripts/adaptive_docx_pipeline.py` based on the template and body output. The starter script supports JSON configuration; for Chinese degree thesis templates, you can directly reuse the built-in preset:

```bash
python skills/docx-template-translator/scripts/adaptive_docx_pipeline.py \
    --template template.docx \
    --body-docx body.docx \
    --out final.docx \
    --config skills/docx-template-translator/presets/zhengzhou_thesis.json \
    --three-line-tables
```

For non-Chinese degree thesis templates, remove `--three-line-tables` and use your own config (or keep the default behavior, which will not modify the font of the main text by default).

5. Final processing:

```bash
python scripts/finalize_word_docx.py final.docx --pdf
python scripts/render_pdf_preview.py final.pdf --pages 1-8
```

## The essence of the difference from pandoc’s default functionality

Pandoc is a "format converter", and this skill is a "template adaptation workflow".

Pandoc’s default capabilities usually stop at: converting content into DOCX and applying the style definitions from the reference document.

This skill aims to do more: it can

- Reconstruct cover and declaration pages according to template semantics.
- Identify the real body, titles, table of contents, and bibliography styles in the template.
- Automatically add figure numbers.
- Convert to three-line tables.
- Fix superscript and hyperlink jumps.
- Fix hyperlink colors.
- Preserve formulas and images.
- Use Word to update table of contents and page numbers.
- Automatically export PDF for visual quality inspection.

## Project status

This is a workflow skill, not an all-in-one converter. Its core value is that each strict Word template has its own local rules, so having AI inspect the template first and then write a specialized Python script is often more reliable than writing a "general converter".

## Known limitations

- **The finalize stage is only supported on Windows.** `finalize_word_docx.py` uses pywin32 to call Microsoft Word COM to update fields/table of contents and export PDF, so it only works on Windows machines with real Word installed. Template inspection, adaptive pipeline, and PDF preview puzzle can run directly on macOS/Linux without Word.
- **Does not support scanned / pure image PDFs.** PDF input requires native digital text layers (pdf2docx / Word import can extract structure), OCR then convert, or use LaTeX / Markdown source files directly.
- **Templates with macros: macros will be disabled.** The finalize stage first sets `Word.AutomationSecurity = msoAutomationSecurityForceDisable`, then opens the document, so any AutoMacros / VBA in the template will not execute. See [SECURITY.md](SECURITY.md) for details.
- **The starter pipeline’s default behavior is conservative.** Three-line table, main text font coverage and other Chinese degree thesis specific processing are opt-in, which need to be enabled via config (refer to `presets/zhengzhou_thesis.json`) or CLI flag. The default behavior will not secretly modify your main text font.
- **Style name recognition covers both English and Chinese templates.** Other localized Word templates (Japanese / Korean, etc.) may need to add `unnumbered_heading_styles` and `body_candidate_styles` in the config.

## Security notice

- The finalize stage will open the user’s provided `.docx` file with the native Microsoft Word. The script defaults to disabling macros, please do not relax this setting on inputs from untrusted sources.
- The skill workflow allows AI agents to generate / modify a specialized Python script based on `adaptive_docx_pipeline.py`. **Please manually review the diff before running the AI-modified script.** The scripts included in this project do not perform any network I/O and only write files to the user-specified output path.
- The complete threat model is detailed in [SECURITY.md](SECURITY.md).

## Compatibility

The skill metadata (SKILL.md with `name` + `description` frontmatter) is designed for Codex, but the format overlaps with the Anthropic Claude Skills specification, so the same skill folder can be slightly wrapped for use in other AI agents.

| Agent / IDE     | Status        | Notes |
| --------------- | ----------- | ---- |
| **Codex**       | Native support     | Directly place in `~/.codex/skills/`, trigger with `Use $docx-template-translator …`. |
| **Claude Code** | Wrapped and usable | SKILL.md’s frontmatter is consistent with Claude Skills specification, can be placed in Claude Skills directory (e.g., `~/.claude/skills/<name>/`) or wrapped as Claude Code plugin. The Python scripts do not need to be changed. |
| **Cursor**      | Manual / Rules | Cursor does not have a native "skill" concept, you can paste the SKILL.md content into `.cursor/rules/*.mdc` and let the agent call `scripts/*.py` directly. |
| **OpenClaw**    | Adaptable | The structure is close to the OpenClaw skill specification, but there is no OpenClaw specific manifest in the repository, so please add metadata before publishing to that platform. |

The scripts themselves are pure CPython and do not depend on any agent runtime - any AI agent that can run shell commands can drive this workflow.
